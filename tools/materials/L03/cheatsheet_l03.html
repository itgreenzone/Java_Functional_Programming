Lambda Expressions in Depth

Java 8 → Java 21 · every error message
below is real javac output

Key rules

  1. Shape: (params) -> expression or (params) -> { statements; return x; } 8
  2. Parentheses are optional only for one parameter with an inferred type.
  3. Expression body returns its value automatically; a block body needs return.
  4. Target typing: a lambda has no type of its own; the context (assignment, argument, return, ?:, cast) decides.
  5. Capture: locals must be final or effectively final. The lambda keeps a copy of the value. Fields are read live.
  6. this = the enclosing instance. A lambda adds no new scope, so a parameter cannot reuse a local's name.
  7. var in parameters 11: all or none; use it only for final or annotations.
  8. Checked exceptions: java.util.function methods declare no throws.

3 · Checked exceptions: wrap once, keep the cause
@FunctionalInterface
interface ThrowingFunction<T,R,E extends Exception> {
    R apply(T t) throws E;
}
raw.stream()
   .map(unchecked(Amounts::parse))  // cause kept
   .toList();

4 patterns for checked exceptions

  1. try/catch inside the lambda (verbose)
  2. custom SAM that declares throws; caller handles it
  3. unchecked(…) wrapper, unwrap at the edge
  4. failure as a value: Optional now, Result in L17

Do / Don't

✔ Do

  • One expression; > 3 lines → named method
  • No side effects in map / filter

✘ Don't

  • Counter hacks
  • Empty catch to make it compile
  • == or lock on a lambda
