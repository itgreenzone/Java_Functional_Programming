Optional, Done Right

Java 8 → Java 21 · results use the shared course dataset
course "today" = 2026-11-07

Key rules

  1. Optional = a box with 0 or 1 value, designed as a return type for "maybe no result". 8
  2. Not for fields, parameters, collections, or replacing every null.
  3. of(x) needs non-null (else NPE) · ofNullable(x) adapts null · empty().
  4. orElse(x) is eager: x is evaluated even when a value is present. orElseGet(supplier) is lazy. Constants → orElse; computations → orElseGet.
  5. map transforms · filter keeps if true · flatMap when the function returns Optional (else Optional<Optional>).
  6. Never get() unchecked; never isPresent() + get(); never return null from an Optional method.
  7. Empty collection, not Optional<List>.

Lesson 05 · sticky notes

Cut out, stick on your wall, and read one every morning.

Optional = return type

"maybe no result".
Not fields, not parameters, not lists.

orElse is EAGER

orElse(x): x always runs.
orElseGet(() -> x): only if empty.

flatMap for lookups

Function returns Optional?
map → Optional<Optional>. Use flatMap.

No get()

Throws "No value present".
Use orElse / orElseGet / orElseThrow.

Never return null

from an Optional method.
return Optional.empty();

Java 9 · 10 · 11

9: or, ifPresentOrElse, stream
10: orElseThrow()
11: isEmpty()

of vs ofNullable

of(null) → NPE now.
Legacy null API? ofNullable.

Empty list, not Optional<List>

An empty collection already means "none".
