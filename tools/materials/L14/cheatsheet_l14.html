Parallel Streams & Performance

Java 8 → Java 21 · results use the shared course dataset
course "today" = 2026-11-07

Key rules

  1. Parallel = split (Spliterator) → run (commonPool + caller) → combine. 8
  2. Sequential by default. Parallel only for large N × Q, CPU-bound, measured.
  3. No shared mutable state. Let collect/toList build results.
  4. reduce: associative operator, neutral identity.
  5. toList/findFirst keep order; forEach/findAny don't.
  6. Never block (HTTP, JDBC) inside a parallel stream: one pool for the whole JVM.
  7. Blocking I/O at scale → virtual threads 21. Timing → JMH.

Canonical snippets

1 · Starting value: add it once, outside reduce
opening.add(payments.parallelStream()
    .map(Payment::amount)
    .reduce(ZERO, BigDecimal::add));   // 4529.84
2 · Safe parallel collection, in order
payments.parallelStream()
    .filter(p -> p.status() == SUCCESS)
    .map(Payment::id).toList();
3 · Blocking I/O: virtual threads
try (var ex = Executors
       .newVirtualThreadPerTaskExecutor()) {
  // submit all, then get() each
}
