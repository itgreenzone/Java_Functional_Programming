Method References

All forms since Java 8 · record accessors Java 16
results use the shared course dataset

Key rules

  1. A method reference is a lambda that calls one existing method. Same behaviour, shorter form. 8
  2. The target type decides how many parameters there are and where they go.
  3. Static Class::m: all parameters → arguments.
  4. Bound obj::m: receiver fixed; parameters → arguments. Receiver evaluated once, at creation; null → NPE at creation.
  5. Unbound Class::m (instance method): 1st parameter = receiver, the rest → arguments.
  6. Constructor Class::new: parameters → constructor arguments. Array Type[]::new: int → length.
  7. Keep a lambda for extra arguments, chains, ambiguous overloads, or when it is clearer.

Canonical snippets

1 · One of each in a real pipeline
payments.stream()
    .filter(Fees::isSuccessful)  // static
    .sorted(Comparator.comparing(
            Payment::amount))      // unbound
    .map(Receipt::from)          // static
    .forEach(printer::print);    // bound
ids = s.toArray(String[]::new);   // array
2 · Unbound with two parameters
BinaryOperator<BigDecimal> ADD = BigDecimal::add;
// (a, b) -> a.add(b): a = receiver, b = argument
accounts.stream().map(Account::balance)
        .reduce(BigDecimal.ZERO, ADD);  // 300382.25
3 · Constructor with 5 parameters
@FunctionalInterface interface CustomerFactory {
    Customer create(String id, String name,
        String city, Tier tier, LocalDate joined);
}
CustomerFactory NEW_CUSTOMER = Customer::new;

Real compiler errors

  • Function<Integer,String> f = Integer::toString;
    → reference to toString is ambiguous (static toString(int) and instance toString())
  • Function<String,Customer> f = Customer::new;
    → invalid constructor reference

Reference or lambda?

✔ Reference when

  • the lambda only forwards
  • the name tells the intent
  • record accessor / constructor
  • you extracted a long lambda

✘ Keep lambda when

  • extra argument: a -> fee(a, RATE)
  • a chain + comparison
  • ambiguous overload
  • the lambda is clearer
