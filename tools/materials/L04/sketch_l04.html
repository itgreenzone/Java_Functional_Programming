2 · Unbound: where do a and b go?

a = the receiver (the object)

b = the argument

perfect for reduce(ZERO, BigDecimal::add) → 300382.25

records [16] → free refs: Transaction::amount

3 · Bound receiver = evaluated ONCE (eager)

null receiver?

code::length with code == null
→ NPE immediately, at creation

() -> code.length()
→ NPE only when called

4 · The shrink ray: lambda → reference

5 · Keep the lambda when…

  • extra argument: a -> fee(a, RATE)
  • a chain: t -> t.amount().compareTo(LIMIT) > 0
  • ambiguous overload
  • the lambda is simply clearer

…or give it a name → ::isHighValue

6 · Integer::toString ?!

fix: i -> i.toString() or String::valueOf

7 · 5 parameters?

JDK stops at BiFunction. Make my own SAM:

CustomerFactory f = Customer::new;

Function<String, Customer> → invalid constructor reference

★ Remember

  • :: = a lambda that calls ONE method
  • unbound: 1st param = receiver
  • bound: receiver evaluated once
  • good method names make refs shine
